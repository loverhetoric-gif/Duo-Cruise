## 1. 目的と前提

MAZDA MX-30 の CarPlay 口につないだ OTTOCAST OttoAibox P3 Pro(以下 OTTO)の 1 つの画面を左右に分け、両方を同時に使う。

| 場所 | 中身 |
|---|---|
| 左(初期) | 自作の CarPlay(iPhone から無線で受ける) |
| 右(初期) | TV 版 YouTube(youtube.com/tv) |

- **操作はコマンダー(ダイヤル)だけで完結させる**。車の画面は触れない前提で、タッチやホームキーに頼る画面・操作は作らない。
- 手元の iPhone・Mac からは、タッチパッドアプリ **Duo Slate** でも操作できる。
- 名前はすべて「Duo Cruise」。Apple の名前やアイコンは使わない。
- 今は本人用。製品として売ることは後々の構想で、仕様の判断は製品の水準で行う。

### 版の呼び名
| 呼び名 | 中身 | 作り方 |
|---|---|---|
| **Duo Cruise Unlimited Edition** | 個人用。今の車で使う版。リリース版の全機能に加え、CarPlay のナビの案内の中身を使う機能([5.5](#55-曲がり角の案内duo-cruise-unlimited-edition-だけ))を持つ | 既定(`assembleDebug`。CI もこれ) |
| **Duo Cruise** | リリース版。ナビの**音声**と連動する機能([5.2](#52-ナビ連動メニュー--画面--画面分割とナビ連動)・[5.3](#53-音の扱い))は入る。ナビの案内の中身を使う機能と、その設定は入らない | `-Pedition=standard` |

- 切り替えはビルド時の 1 か所だけ(`apps/duo/app/build.gradle` の `edition` → `BuildConfig.UNLIMITED`)。リリース版では iPhone に案内の受け口を名乗らず、iPhone との iAP2 のやりとりは今までと同じ

## 4. 配布と更新

1. GitHub(loverhetoric-gif/Duo-Cruise)に変更を入れる
2. 自動ビルドが作って署名する。main に入ったら正式版(build-番号)、PR のときはテスト版(test-番号)
3. OTTO の Duo Cruise Market が新しい版を取って入れる
   - **リアルタイム**: 新しい版を公開した直後に、CI が ntfy.sh の秘密の口(GitHub の Secrets `DUO_PUSH_TOPIC`)へ「check」を送る。車の Duo Cruise はその口を開いたまま待っていて、届いたら更新アプリに今すぐ確認を頼む(中身は check の一言だけ。入るのは署名済みの版だけ)
   - ほかに 15 分ごと(Android の最短)の定期確認と、記録シートの指示 `updater:check`(30 秒ごとに取りに行く)
   - 確認画面なしで更新する(UPDATE_PACKAGES_WITHOUT_USER_ACTION)。確認画面が出たときは、Duo Cruise が前にいても後ろの確認を見つけて押す(指示 `updater:confirm` でも押せる)
   - 新しい版があれば、本体もその場で入れ替え、入れ替えたら本体を開き直す(更新は停車中の検証で行う。2026-10-29 に「起動後 10 分以内だけ」の制限を外した)
   - 「テスト版を受け取る」がオンなら、公開時刻がいちばん新しい版を見る
   - 「1 つ前の版に戻す」ができる
   - Play プロテクトの画面は自動では押さない(本人が操作する)

### 記録シート(本人の Google アカウント)
- シート「Duo Cruise 記録」の「記録」と「指示」の 2 枚。OTTO が受け口(GAS)に送る
- 指示で使える診断: `updater:state` / `check` / `confirm` / `screenshot` / `packages` / `test-channel on|off`、`com.yuki.duocruise.main:state` / `panel` / `swap` / `side` / `car-stop` / `tv-…` など
- **チップに触れる指示と CarPlay の開始は、遠くからは受け付けない**
- 本体が落ちたときは、版・スレッド・例外の先頭 30 行を手元に書き残し、次に開いたときに記録として送る

## 5. 画面

### 5.1 2 画面と 1 画面
- 1 つの画面に左右 2 つの枠。左右の入れ替えは枠の置き直しだけで、YouTube を読み込み直さない
- 入れ替えると、2 つの枠がくるっとすれ違う動き
- **1 画面**: 片方だけを全幅で出す。1 画面の間は「ナビボタン 1 回」(ターゲットの切り替え)で YouTube だけ ⇔ 地図だけ
- 分割比は変えられる(通常の分割比、初期値 50%)

### 5.2 ナビ連動(メニュー › 画面 › 画面分割とナビ連動)
| 設定 | 内容 | 初期値 |
|---|---|---|
| 通常の分割比 | ふだんの左右の幅 | 50% |
| ナビ案内中に自動で調整 | CarPlay のナビ音声が出ている間だけ、分割比を変える | オフ |
| ナビ案内中の分割比 | そのときの幅 | 50% |
| ナビ案内中は地図を運転席側に配置 | 案内の間、地図を運転席の側へ(ハンドルの位置で決まる) | オフ |
| 通常の配置に戻るまでの時間 | 案内が終わってから戻すまで | 5 秒 |

- スライダーは、押して調整に入る → ダイヤルで増減 → 押して確定。Duo Slate からは指でなぞって動かせる。

### 5.3 音の扱い
- CarPlay のナビ音声の間は YouTube の音量を下げ、終わったら戻す(Apple の機器と同じ動き)
- **電話・Siri の間は YouTube を一時停止**し、終わったら、止める前に再生していれば再開する
- YouTube が再生 1〜2 秒で止まる不具合(音の主導権の奪い合い)は直した

### 5.5 曲がり角の案内(Duo Cruise Unlimited Edition だけ)

CarPlay のナビが送ってくる案内の中身(次の曲がり角の曲がり方・そこまでの距離・曲がった先の道路の名前・到着)を使う。メニュー › 画面 › 曲がり角の案内。

| ページ | 設定 | 内容 | 初期値 |
|---|---|---|---|
| 案内の表示 | 表示 | 次の曲がり角を、YouTube の枠の右上に小さく出す(矢印・距離・道路の名前)。表示しない / 地図が見えないとき / 常に | 地図が見えないとき |
| | 表示を始める距離 | 50〜2000 m | 1000 m |
| 地図の自動表示 | 曲がり角で地図を表示 | 曲がり角が近づいたら地図を出す。2 画面は分割比を変え、1 画面で YouTube を出していれば地図に切り替える | オフ |
| | 地図を表示する距離 | | 300 m |
| | 地図表示中の分割比 | YouTube の幅 | 30% |
| | 元に戻るまでの時間 | 曲がり終えてから戻すまで(0〜10 秒) | 3 秒 |
| 方向の光 | 曲がる方向を光で知らせる | 画面全体の、曲がる側(左・右)の縁だけを一瞬光らせる。曲がり角ごとに 1 回。Duo Slate の縁も同じ側が光る | オン |
| | 光らせる距離 | | 200 m |
| | 光の色・強さ | R/G/B・強さ | アンバー・55% |
| 音量の自動調整 | 曲がり角で音量を下げる | 曲がり角の手前で YouTube の音量を下げ、曲がり終えたら戻す | オフ |
| | 音量を下げる距離 | | 150 m |
| | 下げたときの音量 | | 30% |
| 到着時の動作 | 到着時に YouTube を全画面 | 到着したら地図をやめて YouTube を全画面に。次のルートが始まったら元へ | オフ |

- 画面と音を勝手に変える設定は、初期値をオフにしてある
- 曲がる向き: 左・右・やや左右・大きく左右・U ターン(左側通行では右に回る)・ロータリー・到着・直進を矢印で描く。角は丸めない
- 優先: 地図の自動表示 > ナビ音声の分割比 > 到着後の全画面 > 普段の分割比
- 案内の受け取り: iAP2 の識別情報で「案内を受け取る画面」(項目 30)を名乗り、受け口 0 あてに案内を申し込む。断られたら、その項目だけを外して名乗り直す(CarPlay は止めない)。項目の番号は LIVI(GPL-3.0)の iap2-csm と同じ
- 記録: 状態か曲がり角が変わったときだけ「ナビの案内: …」を残す(距離が縮むたびには残さない)
- 確かめ用の指示: 記録シートから `route-test <曲がり方 0〜53> <距離 m>`・`route-end`。停車中に、案内が届いたことにして表示・光・地図・音量を動かせる
- 案内の中身を送るのは Apple のマップなど。ほかのナビアプリが送るかは(未確認)

### 5.6 車の設定(メニュー › システム › 車の設定)

| 設定 | 内容 | 初期値 |
|---|---|---|
| ハンドルの位置 | 右ハンドル / 左ハンドル。運転席がどちらの側かを決める。CarPlay に伝え(iPhone は運転席の側に操作を寄せる)、「ナビ案内中は地図を運転席側に配置」もこれに従う。変えると CarPlay をつなぎ直す | 右ハンドル |
| 距離の単位 | キロメートル / マイル。曲がり角の案内の距離と、距離の設定の表示に使う(Unlimited Edition だけ) | 端末の地域(米・英などはマイル) |
| CarPlay 用の Wi-Fi › | ネットワーク名(SSID)とパスワード。押すと CarPlay をいったん止め、Duo Slate のキーボードの入力を待つ。決定で保存し、つなぎ直す | 未設定 |

- 画面の文言に機種名(OTTO)と、作者の車の SSID を出さない。案内は「この機器の Wi-Fi アクセスポイント」
- 初めて使うときは、ネットワーク名 → パスワードの順に入力を求める
- 名前の設定が無かった版から使っている場合(パスワードだけ保存済み)は、それまでの SSID を名前として引き継ぐ(つなぎ直しは要らない)
- 距離の表し方: km は「300 m」「1.2 km」、マイルは 0.1 mi 未満を「500 ft」(50 ft 刻み)、それ以上を「0.3 mi」

### 5.4 YouTube(TV 版)
- 名乗り(UA)は Tizen(TV)。youtube.com/tv のまま開ける
- **前回の続き**: 動画を再生したまま終わっていれば、次に開いたときその動画の続きから(12 時間以内)
- iPhone の YouTube のキャストボタンから「Duo Cruise」を選ぶと、この画面で再生(DIAL を自作)。実機で iPhone から送れるかは(未確認)
- ステアリングの曲送り・曲戻し・再生/一時停止は、CarPlay が音楽を鳴らしているときは CarPlay へ、それ以外は YouTube へ届ける

## 6. コマンダーの操作

車での実測: コマンダーから届くのは上下左右・決定・戻る・曲送り/戻し/一時停止・ナビボタン(紙飛行機。キー 55=COMMA)だけ。ホームとタスク(♪)は、Duo Cruise をホームアプリにしても機器が先に取るため届かない(2026-10-29 記録で確認)。押してから離すまで 10〜25ms なので**長押しは判定できない**。そのため**押す回数**で分ける。押し込みの 3 回以上は押しにくいので、本来の働きが無いナビボタンを主に使う。

| 操作 | 動き(初期の割り当て。2026-10-29 本人が決定) |
|---|---|
| 回す・倒す | 項目を選ぶ |
| 押す | 決定 |
| ナビボタン 1 回 | ターゲットの切り替え(操作する画面) |
| 押し込み 2 回 | ウィンドウの切り替え(左右の入れ替え) |
| 戻る 2 回 | 1 画面と 2 画面の切り替え |
| ナビボタン 2 回 | 分割比の調整 |
| 押し込み 3 回 | メニューを開く・閉じる |

**分割比の調整**(ナビボタン 2 回。2026-10-29):
- 回すと左右の境目が 5% ずつ動く(右へ回すと境目が右へ)。押し込みで決定、戻るで取り消し、4 秒回さなければ決定
- 調整中は境目だけを細いネオンで灯し、境目の左右にそれぞれの中身と割合(「CarPlay 55%」「YouTube 45%」)、下に操作の案内を出す
- 調整中に割り当ての押し方(2 回押しなど)をしたら決定として扱う。1 画面のときは使えない
- Duo Slate からは、二本指で横になぞって動かせる
- 決めた値は「通常の分割比」(5.2)と同じもの
- ナビボタンに 2 回の割り当てがあるため、ナビボタン 1 回(ターゲットの切り替え)は、2 回目を待つぶんだけ少し遅れる

- 割り当ては メニュー › 操作・カスタマイズ › コマンダーのボタン割り当て で変えられる(連続 1〜4 回、または長押し)。項目は上の 5 つ(表の順)。初期状態に戻せる
- 1 つの動作に 1 つの押し方だけ。すでに別の動作が使っている押し方を登録すると、その動作には、登録した動作が今まで使っていた押し方を渡す(入れ替えて重複させない)
- 保存の名前を keymap5 に変えたので、前の版の割り当ては使わず、この初期値から始まる
- 切り替え・入れ替えのように速さが要るものは、メニューを通さず直接割り当てる
- Duo Cruise 本体にはコマンダーの絵や操作盤は出さない(開発用のコマンダーは Mac の Duo Slate にだけある)

## 7. メニュー(設定ビュー)

押し込み 3 回で開く(割り当ては変えられる)。画面の端から内側へ光る黒の透過の面に、白い文字の縦 1 列。角丸は使わない。

```
メニュー
├── 画面 ›
│   ├── 操作対象の画面(左 / 右)
│   ├── 画面の配置(左 CarPlay/右 YouTube、左 YouTube/右 CarPlay、片方のみ表示)
│   └── 画面分割とナビ連動 ›(5.2 の表)
├── 操作・カスタマイズ ›
│   ├── コマンダーのボタン割り当て ›
│   ├── ネオンの色・強さ ›(ターゲット切替・接続完了・接続不良それぞれの R/G/B と発光の強さ)
│   └── メニューの表示範囲(操作中の画面のみ / 画面全体)
├── システム ›
│   ├── ユーザー補助(オン/オフ)
│   ├── ホームアプリ / ホーム画面を開く
│   ├── Android の設定を開く
│   ├── 起動音(オン/オフ)
│   ├── はじめての案内(もう一度見る)
│   └── 動作記録
├── CarPlay を開始 / CarPlay を終了(接続中 / 停止中)
└── メニューを閉じる
```

- **車載で一目で読めること**: 項目名と値を近づけ、スライダーは太く、パーセントは大きな数字で出す
- **選んでいる行**: ネオンではなく、文字を大きく・行を高く・純白にして示す
- **移り変わり**: 開く・下の階層へ入る・戻る・閉じる、それぞれに動きを付ける
- 文言は一般的なアプリの標準の言葉を使う(内部の呼び名・造語・機種名を出さない)

## 8. 光(ネオン)

**設計思想: 光は自分では動かない。操作に答えて生きる。** Duo Slate(iPhone)の光を録画で計測して決めた。

- **普段(自律)は繊細に**: 明るさの起伏 ±25%(1, 0.75, 1, 0.85)が縁に沿ってごく遅く巡るだけ(約 72 秒で一周)。明滅(呼吸)はしない。普段の強さは 0.30 に抑え、応答が立つ余地を残す
- **応答は大胆に**: コマンダーで選んだ行の近くの縁が灯る(0.15 秒で灯り、0.6 秒で引く)。スライダーの値が動くと光がふっと強まる
- **作り**: 3 層で 1 本の縁(広い裾 46dp・中のにじみ 10dp・外側の細い線 1.6dp)。ぼかしは RenderEffect(GPU)で View ごとにかける
- **メイン画面(CarPlay/YouTube)は没入を優先**し、出来事の瞬間だけ光る: ターゲット切替=白、接続完了=青、接続不良=赤。0.35 秒で灯り、1.3 秒まで保ち、2.4 秒で消える。色と強さ(初期 55)は項目ごとに変えられる。入れ替えでは光らせない

**Android で守ること(破ると CarPlay が黒くなる・描かれない)**
- software レイヤーと BlurMaskFilter は使わない(CarPlay の SurfaceView が黒くなる)
- RenderEffect のぼかしは σ = 0.577×半径 + 0.5。iPhone の数字のままだと約 1.7 倍きついので、28 → 48、7 → 11 に換算する
- 横長の画面で角度(SweepGradient)で模様を回すと長辺がほぼ動かない。模様は「縁に沿った距離」で進める
- 四隅は 45° で突き合わせ、角で重ねない

## 9. 起動・はじめての案内・多言語

- **起動演出**: 一色 → 色付きのシンボルとロゴ(約 2.9 秒)、昼は白地・夜は黒地。詳細は [assets/brand/README.md](../assets/brand/README.md)
- **起動音**: 「ブルーム」(昼と夜で高さを変える)。メニュー › システム › 起動音 で切り替え
- **はじめての案内**: 初めて開いたとき、起動演出のすぐ後に 4 ページ。地の色・差し色を起動演出と地続きにし、最後は地が透けるように 2 画面が現れる。メニュー › システム から何度でも見られる
  1. ふたつの画面を、ひとつに
  2. iPhone と接続する(設定 › 一般 › CarPlay から「Duo Cruise」を選ぶ。次回からは自動)
  3. コマンダーで操作する(6 の表)
  4. iPhone から YouTube を再生する(キャストボタンから「Duo Cruise」)

## 10. 自作 CarPlay

- 土台: xcertplay 1.4.2(GPL-3.0)を `apps/duo/carplay` に取り込み。無線のみ(Bluetooth で接続 → Wi-Fi で映像)
- **開いたら自動で開始し、切れたら自動でつなぎ直す**(間隔は最大 5 分)。メニューから開始・終了もできる
- 映像の口は 7200 番
- 画面の文言は利用者の言葉で出す(「iPhone を待っています」「CarPlay を開始しています」など。9 の多言語に含む)
- ナビ開始で地図を前面に出す・フォーカス移動を有効にする(試験中)

### つながるための決め手(2026-10-27 初接続、10-28 安定)
1. **MFi 認証チップ(i2c-0、0x10/0x11)**: 読む場所を指定してから 10ms 待つ。アプリは 0x11 を使う
2. **Wi-Fi は OTTO 本体のホットスポット**: LocalOnlyHotspot は起動ごとに名前が変わり、iPhone は最初の名前で車を覚えるため、ペアリング直後の 1 回しかつながらなかった。本体のホットスポットは名前が変わらない。パスワードは Duo Slate のキーボードで一度だけ入れ、端末の中にだけ保存する
3. **機器 ID は固定値**(本体のホットスポットは入れるたびに BSSID が変わるため)
4. **返事を約 2 分待つ**: iPhone は Wi-Fi に移る間、Bluetooth(iAP2)の返事を止める。16 秒であきらめると失敗する
5. **ペアリングは OTTO から申し込み**、OTTO の確認画面ですぐ「ペア設定」を押す(iPhone から申し込むと通知だけ出て時間切れ)

チップの中身を書き換える操作はしていない。チップ操作・Play プロテクト・アプリの削除は本人の承認が要る。

## 11. Duo Slate の受け口

## CarPlay の画面の大きさ(2026-10-29 実機で調べた結果)

- iPhone には画面全体 1480×480、実寸 230×90mm(本人の実測)で伝える。実寸を機器の申告(321dpi)から出すと 117×38mm になり、1480×480 を「このディスプレイ解像度に対応していません」と断られた。740 幅は 321dpi でも通っていた。
- 描く範囲(viewAreas)を宣言し、つないだまま切り替える(updateViewArea、iPhone 側が 0.3 秒で描き直す)。範囲はどれも左上が原点、高さ 480。
- 自動の試し(指示 `car-areatest` / `car-areatest 2`)の結果:
  - 範囲 19 個(74 きざみ 148〜1480)を宣言してもつながり、全部を順に切り替えても映像は切れない。
  - ただし画面で確かめると、518 以下の範囲に切り替えると iPhone が「このディスプレイ解像度に対応していません」を映像として映す(映像は切れないので、つながりだけでは判定できない)。592 以上は描かれる。740 に戻せば直る。
  - 奇数の 627 はつながらなかった(偶数でないと断ると見ている)。
  - 画面全体を 1600・1920 と伝えても受けた。画面全体の高さ 520 も受けた。
  - つながった直後(数十ミリ秒)に範囲の切り替えを送ると切られた事があるため、つながって 3 秒待ってから送る。
  - 最初の範囲(initialViewArea)を 1480 にすると「解像度に対応していません」で断られる。最初は必ず 740 で始め、つないで 3 秒後に枠の幅の範囲へ切り替える。
- 一本道(Unlimited Edition): 案内中、次の曲がり角が設定の距離(既定 2km)より遠ければ YouTube を設定の割合(既定 70%)に広げ、300m 近づいたら戻す。2 画面のときだけ。既定はオフ。
- 既定の範囲は分割比 5% きざみ(592〜1480)と、YouTube がちょうど 16:9 になる残り 626。それより細い枠には 592 を縮めて映す。枠の幅に一番近い範囲を選び、枠の幅に合わせて伸び縮みさせる。
